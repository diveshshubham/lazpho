# Lazpho 1.0 readiness gate

This checklist separates verified engineering work from decisions or external state that automation cannot supply. Stable `1.0.0` must not be tagged until every blocker is checked by a maintainer.

## Functional and testing

- [x] Fixed/adaptive concurrency, queues, runtime reconfiguration, retries, breaker, bulkheads, cancellation, timeouts, lifecycle, adapters, metrics, and presets have behavioral coverage.
- [x] Full tests, deterministic stress, short soak, API contract, packed consumers, and package verification pass.
- [x] Long soak has scheduled/manual CI coverage.
- [x] No known timer/listener/partition/accounting leak or shutdown deadlock in the tested contract.
- [x] Signalboard exercises all five MongoDB APIs in direct/Lazpho comparisons and all three Load Lab actions, with Linux CI smoke coverage and retained reports.
- [x] Controlled MongoDB transport latency, connection cuts, breaker recovery, and a mixed-fault application soak have local evidence and a bounded Linux CI gate.

## Compatibility and API stability

- [x] Node 18/20/22/24, TypeScript 5.7.2/current 5.x, framework boundaries, ESM-only behavior, and deep-import policy are documented and automated.
- [x] Runtime exports, public declarations, errors, warnings, presets, metrics, state mappings, and peers are snapshot-protected.
- [x] Every intentionally exported API has a documented category; none is currently marked experimental.
- [ ] Maintainer explicitly accepts `createFactory`, the application integration, Load Lab, current controller/type names, eleven subpaths, and all snapshot contents as the 1.x support surface.

## Documentation and operations

- [x] Consumer quick start, API reference, configuration/adaptive guidance, retry/breaker/bulkhead semantics, cancellation/timeouts/shutdown, adapters, observability, metrics, and troubleshooting exist.
- [x] Compatibility, SemVer, migration/deprecation, security, contribution, changelog, non-goals, and cardinality guidance exist.
- [x] Critical code paths are backed by compiled examples or behavioral/type consumer fixtures.

## Package and release

- [x] The package name is `lazpho`; `0.1.0-rc.1` is publicly installed from npm under the confirmed `dev_divesh_shubham` publisher account.
- [x] Versioned tarball allowlist, metadata checks, all-subpath consumers, checksum, tag/version validation, dry-run, and exact-artifact workflow exist.
- [x] Maintainer controls the `lazpho` npm package and confirmed the actual publisher account.
- [x] Canonical public GitHub repository URL is chosen and added to `repository`, `homepage`, and `bugs` metadata.
- [x] An approved temporary `NPM_TOKEN` fallback is installed for the exact release workflow.
- [ ] npm trusted publishing is configured for `diveshshubham/lazpho` and `release.yml`, provenance is verified on a subsequent prerelease, and the temporary token is revoked.
- [x] Private vulnerability reporting is enabled and documented on the canonical repository.
- [x] Branch protection is enabled on `master` with required cross-version, API, package, stress, and soak checks.
- [x] A real RC validates npm installation, clean-consumer imports, all package subpaths, and the GitHub Release recovery procedure.
- [ ] Maintainer verifies npm README rendering and trusted-publisher provenance on a subsequent prerelease.
- [ ] Maintainer approves the 1.0 release notes and stable-version decision.

## Current verdict

Machine-checkable implementation, documentation, npm ownership, branch protection, and the first real RC are ready. Trusted-publisher provenance, npm README review, production-like external validation, maintainer API acceptance, and the stable-version decision remain blockers.

**Status: NOT_READY_FOR_1_0**

Fancy documentation sites, benchmark dashboards, extra frameworks/presets, CommonJS, Bun/Deno, weighted scheduling, and distributed coordination are explicitly non-blocking.
